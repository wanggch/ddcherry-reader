## 2. 原则与北极星

### 2.1 原则

1. **个人优先**：围绕「一个人用得更舒服」，不做多人协作、云同步、社交。
2. **本地优先**：不上传用户内容，不默认调用外部 API。
3. **稳定优先**：已修好的链路不反复横跳；新能力先测后合。
4. **渐进交付**：每个小版本只聚焦 1～2 个可感知改进。
5. **共享核心**：新功能优先进 `@md-reader/core`，扩展与桌面同步受益；壳层只做平台能力。

暂不把 Freemium / AI / 云同步当主线（扩展侧「付费路线图」与当前个人向桌面客户端目标不一致）。

### 2.2 北极星

> **打开本地 Markdown → 安静阅读 → 改完自动刷新 → 一键导出 / 投递内容**，全程无云、无账号。

可量化成功标准：

1. 日常打开 / 切换文档零摩擦（最近文件、会话恢复、快捷键齐全）
2. 长文可搜、可跳、可专注
3. 导出链路可靠（PDF 已有；公众号 / HTML 补齐）
4. 安装与升级可自用（dmg / nsis 稳定；自动更新视签名预算）

## 3. 分阶段计划

### Phase A · 日常可用性补齐（约 2～3 周）— P0

**目标：** 自己每天愿意用它当默认阅读器。

| # | 项 | 说明 | 落点 |
|---|----|------|------|
| A1 | **会话恢复** | 重启后恢复上次打开的标签 + 活动 tab + 可选滚动位置 | desktop `TabManager` + storage |
| A2 | **最近打开** | 空状态展示最近 N 个文件；菜单 File → Recent；可清空 | desktop storage + menu |
| A3 | **快捷键补齐** | ⌘F 搜索、⌘W 关标签、⌘O / ⌘⇧O、⌘± 字号、⌘\\ 侧栏、⌘. 专注模式等；与原生菜单同步 | desktop + core |
| A4 | **文档内搜索** | Ctrl/Cmd+F：高亮、上下一条、计数；不抢系统查找语义混乱 | **core**（扩展也可受益） |
| A5 | **菜单补全** | Export PDF、Settings、Toggle TOC/Source、Close Tab；修正品牌文案不一致（窗口标题 / About / productName） | `menu.rs` + 事件 |

**验收：** 冷启动能回到昨天的工作区；键盘可完成约 90% 操作，几乎不点工具栏。

---

### Phase B · 内容出口（约 2～3 周）— P0 / P1

**目标：** 阅读器 → 轻度内容工具。

| # | 项 | 说明 | 落点 |
|---|----|------|------|
| B1 | **公众号一键复制** | 按现有方案：core 出「公众号安全 HTML」+ Tauri `writeHtml`；本地图 / Mermaid / 公式明确降级 | core + desktop；扩展后续 |
| B2 | **修 `exportToHtml()`** | 现状实际返回 Markdown 源文，需真正导出独立 HTML（可离线打开，或 body + 内联样式两档） | core |
| B3 | **PDF 体验打磨** | 标题作打印页眉 / 文件名、可选页码；长代码分页做回归 checklist | desktop + print.css |
| B4 | **复制为 Markdown / 纯文本** | 工具栏或菜单：整篇 MD，或选中内容的纯文本降级 | desktop clipboard |

**验收：** 技术文 → 公众号粘贴，标题 / 列表 / 代码块可用；失败类型有明确提示，不静默丢内容。

B1 实施前须按方案做 **阶段 0 实测**（macOS / Windows × 真实公众号编辑器）。

---

### Phase C · 阅读体验深化（约 2～4 周）— P1

**目标：** 长时间读技术文更舒服。

| # | 项 | 说明 |
|---|----|------|
| C1 | **专注 / 禅模式** | 隐藏标签栏 + 工具栏，仅保留正文（Esc 退出）；可记偏好 |
| C2 | **字数 / 预计阅读时间** | 状态栏或弱展示（中文约 300 字 / 分） |
| C3 | **大纲快速跳转面板** | ⌘P / ⌘⇧O 风格：按标题过滤跳转（比侧栏 TOC 更快） |
| C4 | **排版残余** | 样式方案阶段 3～4：版心、引用 / 表格 / admonition、代码语言标签、行软换行偏好 |
| C5 | **阅读进度持久化** | 按文件 path 记住 scroll + 可选 hash 章节 |

**验收：** 5000+ 字文档可搜、可跳、可专注；`samples/` 实机目视通过。

---

### Phase D · 桌面原生与分发（约 3～5 周，可并行）— P1 / P2

| # | 项 | 说明 | 约束 |
|---|----|------|------|
| D1 | **自动更新** | Tauri updater + GitHub Releases | 无签名时 mac 体验差；可先「检查更新 → 打开下载页」 |
| D2 | **代码签名 / 公证** | Apple / Windows 证书 | 架构文档已记「暂无预算」→ 预算到位再做 |
| D3 | **系统集成** | Dock 最近文件、Windows Jump List；「用 DDCherry 打开」安装包实测 | 已有 `fileAssociations`，需实机回归 |
| D4 | **原生感** | 样式阶段 6：traffic lights / 拖拽区、滚动条、`prefers-reduced-motion`、focus-visible | 自用可优先 macOS |
| D5 | **多窗口（可选）** | 新窗口打开另一文件 / 文件夹 | 非必须；标签够用可后置 |

**验收：** `tauri build` 产物可分发给非开发者安装使用；更新路径清晰。

---

### Phase E · 差异化 / 长期（不定时）— P2，评估后再开

| 方向 | 说明 | 近期是否建议 |
|------|------|----------------|
| 幻灯片模式（`---` 分页） | 扩展旧路线图 | 个人用频率低，后置 |
| 分屏对比两个 MD | 标签之上的 layout | 有真实需求再做 |
| 双向编辑写回源文件 | 桌面有写权限 | 会变成编辑器，偏离阅读器，谨慎 |
| 全文索引 / 个人 Wiki | 跨文件搜索 | 工作量大；Obsidian 已覆盖，非优先 |
| 批注高亮本地存 | 本地 JSON / IndexedDB | 有刚需再做 |
| AI 摘要 | 与本地优先冲突 | 默认不做；若做须可选本地模型且默认关 |

## 4. 工程债与横切事项

穿插在每个 Phase，不单独占大版本：

| 项 | 原因 |
|----|------|
| 品牌统一 | `productName` = DDCherry Reader，窗口 title / About 仍混用 Markdown Reader Pro |
| `exportToHtml` 语义修正 | 阻塞 HTML / 公众号导出正确建模 |
| desktop 测试加厚 | 目前 adapters 级测试很少；`TabManager` / 会话恢复需测 |
| core 搜索 / 导出模块可测 | 新逻辑进 core，扩展同步受益 |
| CI：macOS + Windows build | 至少保证 desktop 可编过 |
| 版本与 changelog | workspace 已有 changesets，发版流程写清 |
| system 主题策略 | core 已 migrate 掉 system，但菜单仍有 Follow System → **统一策略** |

## 5. 建议时间线（约 6～8 周）

```text
Week 1-2   Phase A：会话恢复 + 最近文件 + 快捷键 + 搜索骨架
Week 2-3   Phase A 收尾 + 菜单 / 品牌统一
Week 3-5   Phase B：公众号复制（先实测）+ export HTML 修正
Week 5-7   Phase C：专注模式 + 字数 + 跳转面板 + 排版残余
并行       Phase D 轻量项：更新检查、安装包回归、原生感小修
```

每个小版本只合 1～2 个「用户可感知」能力，避免样式 / 功能大杂烩 PR。

---

## 6. 刻意不做（本阶段）

- 账号体系、云同步、付费墙
- 重型 UI 框架重写（保持 vanilla + core）
- 为商业化堆主题数量
- 在扩展与桌面之间再复制一套渲染逻辑
