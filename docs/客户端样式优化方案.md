# 桌面客户端样式优化方案

> 状态：已落地（2026-07-16 实现；同日补完阶段 2 窗口级工具栏 + 阶段 5 system 主题）  
> 范围：DDCherry Reader / Markdown Reader 桌面客户端视觉与交互样式  
> 日期：2026-07-16  
> 相关代码：
> - 共享：`packages/core/src/styles/`（tokens / themes / chrome / content / code 等模块，聚合为 `reader.css`）
> - 桌面：`packages/desktop/src/styles.css`（标签栏、设置面板、空状态等）
> - 主题资产：`highlight-github*.css`、`github-markdown*.css`、`katex.min.css`

---

## 1. 背景与目标

### 1.1 背景

桌面客户端已完成从浏览器扩展到 Tauri 的迁移，核心渲染、主题变量、工具栏、目录、文件树等能力可复用。当前界面“能用”，但整体观感仍偏：

- **扩展壳思维**：大量按钮、文字标签、边框堆叠，桌面应用感不足
- **样式来源分裂**：自研 CSS 变量 + github-markdown-css + highlight.js + 暗色 `!important` 覆盖，叠加后难控
- **阅读体验不够沉浸**：工具栏与标签栏占高度大，正文区信息密度与留白未按“阅读器”优化
- **桌面专属层较薄**：标签栏、空状态、设置面板尚可，但与 macOS/Windows 原生审美未对齐

### 1.2 目标

| 目标 | 说明 |
|------|------|
| 更像原生阅读器 | 减少“网页工具条”感，强化沉浸阅读 |
| 统一视觉语言 | 一套 token + 组件规范，扩展与桌面共享，桌面可有壳层增强 |
| 降低维护成本 | 收敛 `!important` 与重复主题规则，样式可预期 |
| 可分阶段落地 | 小 PR 连续交付，不阻塞功能开发 |

### 1.3 非目标（本期不做）

- 不重写渲染管线 / 不换 Markdown 引擎
- 不引入重型 UI 框架（React/Vue 组件库）作为硬依赖
- 不在本方案阶段做完整品牌 VI / 商店截图包装
- 不强制砍掉全部主题（可先收敛再扩展）

## 2. 现状诊断

### 2.1 样式分层

```text
┌─────────────────────────────────────────────────────────┐
│  desktop/styles.css                                     │
│  标签栏 / 设置弹层 / 空状态 / print 隐藏 chrome          │
├─────────────────────────────────────────────────────────┤
│  core/reader.css                                        │
│  主题 token、工具栏、目录、文件树、正文、代码、灯箱…      │
├─────────────────────────────────────────────────────────┤
│  第三方资产（按需注入 / 静态拷贝）                        │
│  github-markdown-*.css · highlight-github*.css · KaTeX  │
└─────────────────────────────────────────────────────────┘
```

问题不在“有没有样式”，而在**层级职责与桌面场景优先级不清晰**。

### 2.2 主要痛点

#### A. 视觉噪音偏高

- 工具栏按钮统一“边框 + 面板底 + 文字标签”，横向控件过多（目录 / 主题 / 字号 / 导出 / Source / 布局 / 设置）
- 标签栏与工具栏双层 sticky chrome，挤占纵向阅读空间
- 侧栏边框 + 阴影 + 多套 tab 切换，与正文卡片感叠加

#### B. 字体策略不适合桌面阅读

- 正文字体栈默认以 **JetBrains Mono + 霞鹜文楷** 为主，正文偏“代码编辑器 / 手写体”，长文阅读疲劳
- 桌面 `styles.css` 又用系统 UI 字体覆盖 `body`，与 core 内 `markdown-body` 字体栈可能不一致
- 缺独立的 **UI 字体 / 正文衬线或人文无衬线 / 代码等宽** 三套分离

#### C. 主题体系“数量 > 品质”

- 现有 8 套主题（light / paper / mint / vue / dark / night / purple / black）
- token 重复声明（每主题复制 radius、transition、shadow）
- 暗色代码块大量主题选择器 × `!important`，维护成本高
- 桌面端 `github-markdown` 主题 CSS 未必稳定注入，正文基础样式与自研覆盖混杂

#### D. 桌面壳层与核心壳层叠

- 每 tab 一个 `ReaderCore` → 每面板自带工具栏，多标签时重复 chrome
- 标签栏样式独立于工具栏 token 使用方式，细微不一致
- 进度条 `top: 52px` 等硬编码与桌面标签栏高度未联动

#### E. 阅读排版细节未打磨

- 行高、段距、标题层级节奏、最大行宽（measure）偏“文档站”而非“阅读器”
- 代码块、表格、引用、admonition、Mermaid 容器视觉权重不统一
- 亮/暗切换时内容区与 chrome 可能闪烁或对比度失衡

#### F. 无障碍与系统适配不足

- 焦点环、减少动态效果（`prefers-reduced-motion`）、对比度、高分屏字重未系统处理
- Windows / macOS 滚动条、标题栏（traffic lights / 无边框）未纳入样式策略

## 3. 设计原则

1. **内容优先**：chrome 让位正文；默认隐藏次要操作，保留一键可达。
2. **三层字体**：UI / Reading / Mono 严格分离。
3. **Token 驱动**：颜色、间距、圆角、阴影、z-index 全部变量化；主题只改 token。
4. **桌面增强、核心共享**：通用阅读样式进 core；仅桌面才有的标签栏、窗口空状态、native 菜单对齐进 desktop。
5. **少即是多**：主题先做 2 亮 + 2 暗精品，其余进“更多主题”或后续。
6. **可渐进**：每阶段可独立合并、可回滚，不要求一次性大改。

## 4. 目标视觉方向（建议）

### 4.1 产品气质

| 维度 | 建议定位 |
|------|----------|
| 关键词 | 安静、清晰、专业、可长时间阅读 |
| 参考（气质，非抄袭） | Apple Books / Obsidian 阅读视图 / Typora 预览 / VS Code 禅模式（弱化） |
| 避免 | 花哨渐变、过多彩色边框、工具按钮墙 |

### 4.2 布局意象

```text
┌──────────────────────────────────────────────────────────┐
│ [tabs ······]                              [ + ]         │  ← 极薄标签栏（可选自动隐藏）
├──────────┬───────────────────────────────────────────────┤
│  TOC /   │                                               │
│  Files   │            Reading column                     │
│  (可折叠) │         max-width ~ 720–780px                 │
│          │         舒适行高 / 段距                        │
│          │                                               │
└──────────┴───────────────────────────────────────────────┘
        浮动或极简顶栏：字号 · 主题 · 更多（…）
```

### 4.3 信息架构调整建议

| 现在 | 建议 |
|------|------|
| 顶栏塞满操作 | 主操作 3 个内：目录、主题、更多；导出/Source/布局进溢出菜单 |
| 每 tab 完整工具栏 | 桌面改为**窗口级**工具栏 + 标签栏，避免重复 |
| 侧栏常驻大卡片 | 默认可折叠；展开时弱边框或仅分割线 |
| 字号步进器常驻 | 默认放设置 / 快捷键；顶栏可保留精简版 |

## 5. 分阶段优化方案

### 阶段 0：基线与度量（0.5–1 天）

**目的**：改之前能对比，改之后能验收。

- 截取当前 4 个关键画面：空状态、单文件阅读（亮/暗）、多标签 + 侧栏、代码密集文档
- 列出“必改 / 可改 / 不动”清单（与产品确认）
- 约定验收维度：阅读舒适度、chrome 噪音、主题一致性、代码块观感、多标签场景

**产出**：本文件 + 对比截图目录（可选 `docs/style-baseline/`）

---

### 阶段 1：设计 Token 重构（核心，优先）

**目的**：后面所有视觉改动有稳定地基。

#### 1.1 Token 分层

```text
primitive  →  brand / neutral 色阶、字号阶梯、间距阶梯
semantic   →  --bg / --panel / --text / --muted / --border / --accent ...
component  →  --toolbar-height / --tab-height / --content-measure / --sidebar-width
```

#### 1.2 建议新增 / 拆分的关键 token

| Token | 用途 |
|-------|------|
| `--md-reader-font-ui` | 标签栏、按钮、设置 |
| `--md-reader-font-reading` | 正文（优先系统或人文无衬线，中英混排友好） |
| `--md-reader-font-mono` | 仅代码 |
| `--md-reader-content-measure` | 正文最大宽度（如 `42rem`） |
| `--md-reader-content-leading` | 正文行高（如 `1.7–1.8`） |
| `--md-reader-space-*` | 4/8 间距阶梯 |
| `--md-reader-chrome-height` | 标签栏 + 工具栏合计，供 sticky / progress 对齐 |
| `--md-reader-code-bg` | 代码块背景（独立于 panel，避免暗色 `!important` 大战） |

#### 1.3 主题声明方式

- 公共结构（radius、shadow、transition）提到 `:root` 一次
- 各主题只覆盖颜色语义 token
- 暗色代码块用 **语义 token** 表达，而不是 4 套主题选择器复制粘贴

#### 1.4 验收

- 切换 8 主题时，无未定义变量回退到“刺眼默认色”
- 扩展与桌面同 token 同源

---

### 阶段 2：桌面 Chrome 重构（桌面体验核心）

**目的**：让应用“像桌面阅读器”，而不是“带标签的网页”。

#### 2.1 标签栏

- 高度压缩（约 32–36px），接近浏览器/编辑器标签而非大按钮
- 活跃标签：底边强调色或轻量 pill，减少双边框
- 关闭按钮：默认弱化，hover/active 再显现（或始终小 ×）
- 溢出：左右滚动 + 可选下拉“已打开文件”
- 与窗口拖拽区协调（macOS `data-tauri-drag-region` 预留）

#### 2.2 工具栏

- **方案 A（已实现 / 桌面）**：窗口级单一工具栏，不随 tab 内容重复（`showToolbar: false` + `WindowChrome`）
- **方案 B（扩展默认）**：保留 per-tab 工具栏，desktop density 下 icon-only
- 操作收敛：
  - 一级：目录、主题、更多
  - 二级（更多菜单）：Source、布局、导出 PDF、设置、字号
- 主题菜单：增加色点预览，减少纯文字列表感

#### 2.3 进度条

- 贴齐 chrome 底边，使用 `--md-reader-chrome-height`，避免硬编码 `52px`
- 多标签时位置正确，不与标签栏重叠

#### 2.4 空状态

- 更大的拖放热区视觉、简短快捷键提示（⌘O 打开文件 / ⌘⇧O 打开文件夹）
- 弱插画或线性图标，避免空旷廉价感

#### 2.5 设置面板

- 分组：外观 / 阅读 / 行为
- 控件对齐桌面表单规范（标签左、控件右或上下表单）
- 主题选择改为网格色板，而不仅是 `<select>`

---

### 阶段 3：阅读排版与正文观感

**目的**：打开 Markdown 就想继续读。

#### 3.1 版心与节奏

| 项 | 建议 |
|----|------|
| 最大行宽 | 约 68–78 字符 / `40–46rem` |
| 正文字号默认 | 16–17px（可配置） |
| 行高 | 1.7–1.85 |
| 段距 | 与行高成比例，避免“挤”或“散” |
| 标题 | 缩小 h1 夸张度，加强 h2/h3 层级差与上下留白 |
| 满屏模式 | 仍限制可读行宽，或提供“真正拉满”与“舒适满屏”两档 |

#### 3.2 字体策略

**推荐默认（桌面）：**

- UI：系统 UI 字体（San Francisco / Segoe UI）
- 正文：系统文本文字栈，中文优先「苹方 / 微软雅黑 / 思源」；可选启用霞鹜文楷作为“纸感”主题专用
- 代码：JetBrains Mono / SF Mono / Cascadia Code

**原则**：正文默认不再使用等宽字体；文楷作为 paper 主题特色，而非全局强制。

#### 3.3 组件级正文样式

逐项统一（在 core 中完成，桌面同步受益）：

- 引用块：左边强调线 + 柔和底，避免过重灰块
- 表格：表头弱底、行悬停、横向滚动容器圆角一致
- 列表 / 任务列表：checkbox 与主题 accent 对齐
- 脚注、目录锚点、header-anchor：默认更淡，hover 再显现
- Admonition：按 info/warn/danger 使用语义色，暗色下降低饱和
- Mermaid：容器边框与代码块同半径；暗色主题下图表主题联动（逻辑可后续）

#### 3.4 与 github-markdown-css 的关系

**建议路径（二选一，需拍板）：**

| 路径 | 做法 | 利弊 |
|------|------|------|
| **A. 渐进剥离** | 保留 github-markdown 作基础，逐步用自研 token 覆盖 | 改动小，长期仍有外部约束 |
| **B. 自研正文样式** | 只保留 highlight + KaTeX，正文全自研 | 可控性强，一次性工作量大 |

推荐：**阶段 3 走 A，阶段 5 评估是否上 B**。

---

### 阶段 4：代码高亮与“技术文档”观感

**目的**：修完路径 bug 之后，进一步把代码块做成产品级。

- 代码块圆角、内边距、行号与复制按钮对齐规范
- 亮色：浅底 + 细边；暗色：独立 `--md-reader-code-bg`，取消大片 `!important` 选择器矩阵
- 语言标签（`js` / `ts` / `rust`）可选显示在代码块右上
- 行号与正文滚动同步、复制按钮不遮挡首行
- 行内 code 与 fenced block 对比度分层（行内更轻）
- 长行：横向滚动条样式与主题一致；考虑“软换行”偏好（设置项，后续）

---

### 阶段 5：主题精品化

**目的**：少而精，而不是多而糙。

#### 5.1 默认推荐矩阵

| ID | 定位 | 备注 |
|----|------|------|
| `light` | 默认日间 | GitHub 清爽向，但降低灰底脏感 |
| `paper` | 纸感阅读 | 文楷可选、暖底、低对比边框 |
| `dark` | 默认夜间 | 提高正文对比，避免发灰发闷 |
| `black` | OLED / 专注 | 近纯黑，强调色克制 |

`mint` / `vue` / `night` / `purple`：降级为“附加主题”或合并进进阶列表，避免设置里平铺 8 个难选。

#### 5.2 主题切换体验

- 交叉淡入（可选，注意性能）— 已实现：`.md-reader-theme-animating` 短过渡
- 跟随系统（`system`）在桌面菜单与设置中更明显 — 已实现：设置首项 + 原生菜单 “Follow System”
- 代码高亮 CSS 与正文主题同步，避免“壳暗、代码亮” — 已有 `injectHighlightTheme` + system 监听

#### 5.3 自定义 CSS

- 保持 `@import` 能力
- 文档化可覆盖的 token 列表，鼓励用户改 token 而不是硬扫选择器

---

### 阶段 6：桌面原生感与系统适配

**目的**：跨平台“像样”。

| 平台 | 优化点 |
|------|--------|
| macOS | 流量灯避让、vibrancy/toolbar 材质可选、圆角窗口与内容边距 |
| Windows | 标题栏/Snap 布局预留、Segoe 字体、滚动条宽度 |
| 通用 | `color-scheme`、选区颜色、focus-visible、reduced-motion、打印样式已有基础上再精修 |

额外：

- 深色模式与 OS 一致时的自动切换动画策略
- 拖放文件夹/文件时的 overlay 与系统光标反馈统一

---

### 阶段 7：工程化与可维护性

**目的**：样式不再变成“不敢动的大文件”。

#### 7.1 文件拆分建议（core）

```text
styles/
  tokens.css          # primitive + semantic
  themes/*.css        # 每主题仅颜色
  chrome.css          # toolbar / progress
  sidebar.css         # toc / files
  content.css         # markdown-body 排版
  code.css            # pre/code/copy/line-no
  overlays.css        # lightbox / drop / settings hooks
  print.css
  reader.css          # 聚合入口 @import
```

桌面保持：

```text
desktop/src/styles.css
  tabs / window chrome / empty / settings / print chrome hide
```

#### 7.2 约定

- 禁止新增跨主题复制粘贴选择器；优先 token
- `!important` 需注释原因，并登记清理 backlog
- 视觉改动附 before/after 截图（关键路径）
- 可选：Storybook 或静态 HTML fixture 预览各主题（低成本可用 `samples/*.md` + 截图脚本）

#### 7.3 与扩展的边界

- **共享**：token、正文、侧栏、代码块
- **桌面独有**：多标签、窗口空状态、native 菜单触发的设置壳
- 扩展继续可用较“工具化”的工具栏密度；桌面走更克制的密度（可用 data-attribute 切换 density）

| PR | 内容 | 风险 | 预估 |

| PR7 | 系统适配 / 无障碍 / 打印精修 | 低 | 1d |
| PR8 | CSS 文件拆分与文档化 token | 低 | 1d |

**建议先做 PR1–PR3**：用户对“不满意”的体感提升最大。

## 7. 决策清单（实现前需确认）

1. **工具栏归属**：窗口级统一 vs 每 tab 一套？
2. **正文默认字体**：系统 UI 文本文字 vs 霞鹜文楷全局 vs 仅 paper 主题文楷？
3. **主题数量**：保留 8 个平铺，还是 4 个主推 + 更多？
4. **github-markdown-css**：继续依赖还是中期自研正文？
5. **桌面密度**：默认舒适阅读（宽留白）还是高信息密度（靠近 IDE）？
6. **品牌名展示**：工具栏 “MD Reader” 是否改为 “DDCherry Reader”，是否弱化品牌占位？

## 8. 验收标准（Definition of Done）

### 观感

- [x] 默认主题下，首屏 chrome 高度占比下降（工具栏 icon 化 + 薄标签栏 + 更多菜单）
- [x] 连续阅读 3 屏以上不觉得按钮抢注意力（一级仅 目录/主题/更多）
