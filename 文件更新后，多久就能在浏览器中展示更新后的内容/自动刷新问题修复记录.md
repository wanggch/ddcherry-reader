# 自动刷新问题修复记录

## 问题描述

修改本地 md 文件后，浏览器中展示的内容不会自动更新为最新内容。

## 根本原因

两个问题叠加导致：

1. **`autoRefresh` 默认值为 `false`**：`preferences.js` 中 `autoRefresh` 默认关闭，`startAutoRefresh()` 和 `checkFileChange()` 都会在该值为 `false` 时跳过，导致轮询定时器根本不会启动。

2. **Content script 无法直接读取 file:// URL**：Chrome 的安全策略禁止 content script 通过 XHR 或 fetch 访问 `file://` 协议的 URL（即使是同一个文件），会报 CORS 错误：
   ```
   Access to XMLHttpRequest at 'file:///...' from origin 'null' has been blocked by CORS policy
   ```

## 排查思路

### 尝试过的方案（失败）

| 方案 | 失败原因 |
|------|----------|
| Content script 中用 XHR 读取 file:// URL | Chrome CORS 策略完全阻止，`onerror` 触发，控制台循环报错 |
| Content script 中用 fetch 读取 file:// URL | 同上，CORS 阻止 |
| Background service worker 中用 fetch（无文件权限） | Chrome 扩展默认不能访问 file:// URL，报 "Not allowed to load local resource" |
| Offscreen document 中用 XHR | 方案过于复杂，且导致消息传递链路断裂，自动刷新功能失效 |
| 设置 XHR 请求头 Cache-Control/Pragma | 浏览器禁止设置这些 unsafe headers |

### 关键发现

- Chrome 扩展的 background service worker 可以 `fetch('file://...')`，**但前提是用户在 `chrome://extensions` 中启用了"允许访问文件网址"权限**。
- Content script 无论如何都不能直接发起 file:// 的网络请求（XHR/fetch 都不行）。
- `manifest.json` 中的 `"type": "module"` 不能删除，否则 service worker 无法正常加载。

## 最终解决方案

### 架构

```
content script (每2秒轮询)
    │
    │ chrome.runtime.sendMessage({ action: 'readMarkdownSource' })
    ▼
background service worker
    │
    │ fetch(sender.tab.url, { cache: 'reload' })
    ▼
本地文件系统 → 返回文件内容 → content script 对比 hash → 有变化则重新渲染
```

### 具体改动

1. **`preferences.js`**：`autoRefresh` 默认值改为 `true`。

2. **`content-script.js`**：
   - `startAutoRefresh()`：对 `file://` 页面始终启动 2 秒轮询定时器，不依赖 `autoRefresh` 设置。
   - `checkFileChange()`：通过 `chrome.runtime.sendMessage` 让 background 读取文件，对比 hash 决定是否重新渲染。
   - `injectCustomCss()`：本地 CSS 文件也通过 background 读取，避免 CORS 错误。

3. **`background.js`**：
   - 处理 `readMarkdownSource` 消息：从 `sender.tab.url` 获取文件路径，用 `fetch(url, { cache: 'reload' })` 读取文件内容返回给 content script。
   - 处理 `readFileContent` 消息：用于读取本地 CSS 文件。

4. **`manifest.json`**：
   - 保留 `"type": "module"`。
   - `host_permissions` 包含 `"file:///*"`。

### 前置条件

用户需要在 `chrome://extensions` 中找到 Markdown Reader Pro，启用 **"允许访问文件网址"**（Allow access to file URLs）。这是 Chrome 的安全限制，扩展默认不能访问本地文件内容。

## 经验教训

1. Chrome 对 `file://` 协议有严格的安全限制，content script 的 origin 为 `null`，任何网络请求都会被 CORS 阻止。
2. Background service worker 的 `fetch` 能访问 `file://` URL，但需要用户手动授权。
3. 修复 bug 时应该保持最小改动原则，验证通过后再处理次要问题（如控制台警告），避免在修复警告时破坏核心功能。
4. `manifest.json` 中的配置项（如 `type: module`）不要随意删除。
